CENTRE · OWNER / SOURCE / PUBLICATION

How to change the library safely.

Every public document starts with a reviewed row in the same live Google Sheet. Change display and approval entries there; edit underlying source files only at their original Google Drive locations.

Open live Project Resources workbook

01 · SHEETS → DERIVED FILES

One publisher, three source tabs

GitHub Actions authenticates read-only to one existing Google Sheet and reads these three tabs twice to guard against changes during publication. It does not browse every Drive folder or check each source file live.

project_resources

Company, project, document slot, display name, discipline, format, revision note, approval status, Drive source URL and Publish. The new website filters use only these source fields.

Edit resource rows→ catalog.json (companies, projects and resource records)
client_document_packets

Project A/B/C documents, original PDF identity, language, version, approval note, Publish and source-verified Company. Existing IDs and URLs were preserved.

Edit A/B/C packet rows→ document-packets.json, catalog.json (packet counts)
resource_source_readback

Drive identity, MIME type, recorded modification, original access, observation date and public-listing admission basis.

Review source readbacks→ admission gate for both outputs; reviewed receipt must be 30 days old or less

Source custody is different: Operations & Source Custody is a dated, versioned GitHub file (site/source-custody.json). It reads no worker Sheets and is not an operational payroll dashboard.

03 · DRIVE ORIGINALS

Originals stay at their existing addresses

A resource row records the original Google Drive file or folder ID. The published link opens Drive and respects the original sharing controls. The website does not copy the original PDF, CAD file, wage data, or approval sheet.

Private Fishtail payroll, worker Money & Goods and historical Wage List conversions are owned separately by their original Drive collections. Those private sources are not fetched by this Pages workflow.

Public listing verified, 10 November 2026: both live master project registers report PRJ-000029 is_public=TRUE, and all six original A/B/C packet rows have Publish=TRUE. The historical read-first restriction is superseded for listing. Signed agreements, construction drawing approval and original Google Drive access remain separate requirements.

04 · ACTIONS & PUBLICATION

What happens after a Sheet edit?

  1. Keep the original record ID, original Drive URL, and source readback aligned.
  2. The existing scheduled workflow checks the live owner workbook hourly (GitHub may delay scheduled starts), or an authorized operator can run it manually.
  3. A read-only federated Google connection reads three tabs twice and validates the explicit Publish, source ID, link, MIME, receipt and age gates.
  4. Only the selected static website files and public-safe JSON are uploaded to GitHub Pages.
  5. The verified deployment and source Git commit become the release evidence. A completed workflow proves only its configured checks.

05 · A7 MEMORY PALACE

One authority, reversible changes.

Drive preserves · GitHub versions · Actions validates · Pages presents. The A7 semantic registry governs global identity and routing; it does not replace this repository's source files or your live Google Sheets.

Use Git commit history and milestone tags for website/code PRE and POST, and native Google Sheet history plus existing archives for Sheet changes. Do not clone a Sheet to get a fresh ID, create artificial A7 sequence numbers, or claim private A9 Main/Local archival acknowledgment without evidence.
